## Phase 1: 프로젝트 세팅 및 핵심 게임 구현 (Sprint 1)

### 목표
369 게임의 핵심 로직과 기본 UI를 구현하여, 난이도/타이머 없이 컴퓨터와 번갈아가며 게임을 플레이할 수 있는 상태를 만든다.

### 작업 목록

- 예정 **프로젝트 초기 세팅** (복잡도: 낮음)
  - Vite + React + TypeScript 프로젝트 생성 (`npm create vite@latest`)
  - 불필요한 보일러플레이트 코드 제거
  - 글로벌 CSS에 `font-family: '맑은 고딕', 'Malgun Gothic', sans-serif` 설정
  - `npm run dev`로 localhost:3000(또는 5173) 정상 구동 확인

- 예정 **369 게임 핵심 로직 함수 구현** (복잡도: 중간)
  - `countClaps(n: number): number` - 숫자 n에 포함된 3, 6, 9의 개수를 반환하는 순수 함수
    - 예: `countClaps(3)` -> 1, `countClaps(39)` -> 2, `countClaps(333)` -> 3, `countClaps(12)` -> 0
  - `getCorrectAction(n: number): { type: 'shout' | 'clap', value: string }` - 현재 숫자에 대한 올바른 행동을 반환
    - 3/6/9 미포함 시: `{ type: 'shout', value: '숫자' }`
    - 3/6/9 포함 시: `{ type: 'clap', value: '/박수/' 반복 }` (포함 횟수만큼)
  - 각 함수에 대한 단위 테스트 작성 (최소 10개 케이스)

- 예정 **게임 상태 관리 구현** (복잡도: 중간)
  - 게임 상태 타입 정의: `currentNumber`, `turn` ('computer' | 'user'), `gameOver`, `displayText`, `actionText`
  - 게임 시작 시 `currentNumber = 1`, 컴퓨터 턴부터 시작
  - 컴퓨터 턴: 올바른 행동을 자동 수행 후 숫자 증가, 턴 전환
  - 사용자 턴: 버튼 입력 대기
  - 사용자 입력 검증: 올바른 행동과 비교하여 일치하지 않으면 `gameOver = true`

- 예정 **게임 UI 레이아웃 구현** (복잡도: 중간)
  - 현재 숫자 표시: 페이지 정중앙, 글자 크기 25px
  - 행위 텍스트 표시: 숫자 바로 아래 배치 (컴퓨터/사용자의 행동 결과)
  - "숫자외치기" 버튼과 "박수" 버튼: 행위 텍스트 아래, 가로 배치, 각 100px x 50px
  - 게임 종료 시 현재 숫자 위치에 "게임 종료" 텍스트 표시
  - 모든 컨트롤의 viewport 상대 위치 고정 (CSS: position 기반 레이아웃)

- 예정 **리셋 기능 구현** (복잡도: 낮음)
  - 리셋 버튼 클릭 시 게임 상태를 초기 상태로 복원
  - `currentNumber = 1`, `gameOver = false`, 컴퓨터 턴 재시작

### 완료 기준 (Definition of Done)
- `npm run dev`로 정상 구동
- 페이지 중앙에 현재 숫자가 표시됨
- 컴퓨터가 먼저 올바른 행동을 수행하고 사용자 턴으로 전환됨
- 사용자가 "숫자외치기" 또는 "박수" 버튼을 눌러 응답 가능
- 올바른 응답 시 다음 숫자로 진행, 잘못된 응답 시 "게임 종료" 표시
- 리셋 버튼으로 게임 재시작 가능
- `countClaps`, `getCorrectAction` 단위 테스트 전체 통과

### Playwright MCP 검증 시나리오
> `npm run dev` 실행 후 아래 순서로 검증

**기본 렌더링 검증:**
1. `browser_navigate` -> `http://localhost:5173` 접속
2. `browser_snapshot` -> 페이지 중앙에 숫자 "1" 표시 확인
3. `browser_snapshot` -> 컴퓨터가 "1" 외치기 행동 표시 확인
4. `browser_snapshot` -> "숫자외치기", "박수" 버튼 2개 존재 확인
5. `browser_console_messages(level: "error")` -> 콘솔 에러 없음 확인

**게임 플레이 검증:**
1. `browser_snapshot` -> 컴퓨터가 1을 외친 후 사용자 턴(숫자 2) 확인
2. `browser_click` -> "숫자외치기" 버튼 클릭 (숫자 2에는 3/6/9 없으므로 정답)
3. `browser_snapshot` -> 숫자가 3으로 진행, 컴퓨터 턴 확인
4. `browser_snapshot` -> 컴퓨터가 숫자 3에 대해 "/박수/" 행동 수행 확인
5. `browser_snapshot` -> 사용자 턴(숫자 4) 확인

**게임 종료 검증:**
1. `browser_navigate` -> 페이지 새로고침
2. (컴퓨터 턴 완료 대기 후) 사용자 턴에서 `browser_click` -> "박수" 버튼 클릭 (숫자 2에 박수는 오답)
3. `browser_snapshot` -> "게임 종료" 텍스트 표시 확인

**리셋 검증:**
1. `browser_click` -> "리셋" 버튼 클릭
2. `browser_snapshot` -> 숫자가 1로 초기화, 컴퓨터 턴 재시작 확인

### 기술 고려사항
- 게임 로직(`countClaps`, `getCorrectAction`)은 순수 함수로 분리하여 테스트 용이성 확보
- 컴퓨터 턴 수행 시 약간의 딜레이(예: 500ms~1s)를 넣어 사용자가 진행 상황을 인지할 수 있도록 함
- viewport 상대 위치 고정: `position: fixed` 또는 `vh/vw` 단위 활용
- 버튼 사이즈 100px x 50px은 CSS에서 고정값으로 지정

## Phase 2: 난이도 시스템 및 키보드 단축키 (Sprint 2)

### 목표
난이도별 시간 제한 기능과 키보드 단축키를 추가하여 게임의 완성도를 높인다.

### 작업 목록

- 예정 **난이도 설정 UI 구현** (복잡도: 낮음)
  - "쉬움", "보통", "어려움" 버튼 3개 생성, 가로 배치
  - 버튼 위치: 페이지 우측 상단 (CSS `position: fixed`, `top`, `right`)
  - 각 버튼 사이즈: 100px x 50px
  - 현재 선택된 난이도를 시각적으로 구분 (예: 배경색 변경)
  - 기본 선택값: "보통"

- 예정 **타이머 기능 구현** (복잡도: 중간)
  - 사용자 턴 시작 시 타이머 카운트다운 시작
  - 난이도별 제한 시간: 쉬움 5초, 보통 3초, 어려움 1초
  - 남은 시간을 UI에 표시 (숫자 또는 프로그레스 바)
  - 시간 초과 시 게임 종료 처리 ("게임 종료" 표시)
  - 컴퓨터 턴에서는 타이머 비활성화
  - `useEffect` + `setInterval`로 구현, cleanup 처리 필수

- 예정 **리셋 버튼 위치 조정** (복잡도: 낮음)
  - 리셋 버튼을 난이도 "어려움" 버튼 하단에 배치
  - 리셋 시 난이도 설정은 유지, 게임 상태만 초기화

- 예정 **키보드 단축키 구현** (복잡도: 낮음)
  - `a` 키: "숫자외치기" 버튼과 동일 동작
  - `l` 키: "박수" 버튼과 동일 동작
  - `useEffect`로 `keydown` 이벤트 리스너 등록
  - 게임 종료 상태에서는 단축키 무시
  - 컴퓨터 턴에서는 단축키 무시

### 완료 기준 (Definition of Done)
- 우측 상단에 난이도 버튼 3개가 가로로 표시됨
- 난이도 변경 시 타이머 제한 시간이 변경됨
- 사용자 턴에서 제한 시간 내 미응답 시 "게임 종료" 표시
- 타이머 남은 시간이 UI에 표시됨
- `a` 키로 숫자외치기, `l` 키로 박수 동작 확인
- 리셋 버튼이 어려움 버튼 하단에 위치
- 게임 종료/컴퓨터 턴 시 단축키 및 버튼 비활성화

### Playwright MCP 검증 시나리오
> `npm run dev` 실행 후 아래 순서로 검증

**난이도 UI 검증:**
1. `browser_navigate` -> `http://localhost:5173` 접속
2. `browser_snapshot` -> 우측 상단에 "쉬움", "보통", "어려움" 버튼 3개 확인
3. `browser_snapshot` -> "보통" 버튼이 기본 선택 상태 확인
4. `browser_snapshot` -> 리셋 버튼이 어려움 버튼 하단에 위치 확인
5. `browser_click` -> "쉬움" 버튼 클릭
6. `browser_snapshot` -> "쉬움"이 선택 상태로 변경 확인

**타이머 검증:**
1. `browser_navigate` -> 페이지 새로고침
2. `browser_click` -> "쉬움" 난이도 선택 (5초)
3. `browser_snapshot` -> 사용자 턴에서 타이머 표시 확인
4. `browser_wait_for` -> 5초 대기
5. `browser_snapshot` -> 시간 초과로 "게임 종료" 표시 확인

**키보드 단축키 검증:**
1. `browser_navigate` -> 페이지 새로고침
2. (컴퓨터 턴 완료 대기 후) `browser_type` -> `a` 키 입력 (숫자 2 외치기)
3. `browser_snapshot` -> 다음 숫자로 진행 확인
4. `browser_console_messages(level: "error")` -> 콘솔 에러 없음 확인

### 기술 고려사항
- 타이머는 `useEffect`의 cleanup 함수에서 반드시 `clearInterval` 호출
- 난이도 변경은 현재 진행 중인 게임에 즉시 반영 (게임 리셋 없이 타이머만 변경)
- 키보드 이벤트는 `window`에 등록하되, input 요소 포커스 시 충돌 방지 고려
- 타이머 정확도: `setInterval` 1초 단위로 충분 (ms 단위 정밀도 불필요)

## Phase 3: 통합 검증 및 폴리싱 (Sprint 3)

### 목표
모든 기능의 통합 동작을 검증하고, 엣지케이스를 처리하며, UI/UX를 다듬어 완성도 높은 게임을 만든다.

### 작업 목록

- 예정 **엣지케이스 처리** (복잡도: 중간)
  - 숫자가 큰 경우 (예: 33, 39, 333 등) 박수 횟수 정확성 검증
  - 게임 종료 후 버튼/단축키 완전 비활성화 확인
  - 컴퓨터 턴 진행 중 사용자 입력 방지 확인
  - 빠른 연타 입력 방지 (디바운싱)
  - 난이도 변경 + 리셋 동시 동작 시 상태 일관성

- 예정 **UI 폴리싱** (복잡도: 낮음)
  - 컴퓨터 턴/사용자 턴 구분을 위한 시각적 피드백 (색상, 텍스트)

  - 버튼 hover/active 상태 스타일링
  - 전체 레이아웃 viewport 상대 위치 재검증 (브라우저 리사이즈 시 위치 유지)

- 예정 **코드 품질 정리** (복잡도: 낮음)
  - TypeScript strict 모드 경고 해소
  - 미사용 import/변수 제거
  - 컴포넌트 분리가 필요한 경우 최소한으로 리팩토링
  - 코드 주석 정리 (한국어)

- 예정 **전체 기능 통합 테스트** (복잡도: 중간)
  - 게임 시작부터 종료까지 전체 시나리오 테스트
  - 난이도별 타이머 동작 테스트
  - 연속 리셋 후 정상 동작 테스트
  - 키보드 단축키와 버튼 클릭 혼용 테스트

### 완료 기준 (Definition of Done)
- PRD의 모든 요구사항이 구현 및 검증됨
- 콘솔 에러/경고 없음
- TypeScript 컴파일 에러 없음
- 브라우저 리사이즈 시 레이아웃 깨지지 않음
- 게임을 30 이상까지 정상 진행 가능 (다양한 3/6/9 조합 검증)
- 모든 난이도에서 타이머 정상 동작

### Playwright MCP 검증 시나리오
> `npm run dev` 실행 후 아래 순서로 검증

1. `browser_navigate` -> `http://localhost:5173` 접속
2. `browser_snapshot` -> 초기 상태: 숫자 1, 컴퓨터 턴 확인

7. `browser_console_messages(level: "error")` -> 에러 없음

**난이도 변경 후 게임 플레이 검증:**
1. `browser_click` -> "어려움" 난이도 선택
2. `browser_click` -> 리셋 버튼 클릭
3. `browser_snapshot` -> 게임 초기화, 타이머 1초 제한 확인
4. (1초 초과 대기) `browser_snapshot` -> 시간 초과 "게임 종료" 확인

**반응형 레이아웃 검증:**
1. `browser_resize` -> 모바일 크기 (375x667)
2. `browser_snapshot` -> 모든 컨트롤의 상대 위치 유지 확인
3. `browser_resize` -> 데스크톱 크기 (1920x1080)
4. `browser_snapshot` -> 레이아웃 정상 확인

**엣지케이스 검증:**
1. 게임 종료 상태에서 `browser_click` -> 버튼 클릭 -> 반응 없음 확인
2. `browser_click` -> 리셋 -> 정상 재시작 확인
3. `browser_console_messages(level: "error")` -> 전체 과정에서 에러 없음

### 기술 고려사항
- 엣지케이스 처리 시 기존 로직 변경을 최소화하고, 방어적 조건문 추가
- 리팩토링은 동작 변경 없이 구조만 개선 (테스트 통과 상태 유지)
- Karpathy 원칙 준수: 불필요한 추상화 금지, 요구되지 않은 기능 추가 금지
